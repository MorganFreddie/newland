01-Git 初学者入门简介 | GitHub
A brief introduction to Git for beginners | Github
Git 初学者入门简介 | GitHub
​ ​
1.
何为git
1.
git 是世界上使用最广泛的版本控制系统。
2.
版本控制系统是一个跟踪文件在一段时间内更改的系统
3.
git基础概念
1.
工作目录 是修改文件的地方
2.
暂存区 是你准备提交更改的地方，类似于草稿箱
3.
本地仓库 是存储在你的计算机上的项目历史记录，它包含所有的提交和分支，作为项目更改的个人记录
4.
远程仓库 是托管在互联网或网络上的项目版本，它允许多人协作，向共享资源分支推送和从共享资源分支拉去代码是项目的并行版本，它们允许你独立地处理不同功能或修复，而不会影响主项目，直到您准备将它们合并回主项目。
5.
拉取请求 是将更改从一个分支提交到另一个分支的方式，它请求审查、讨论、并将可能更改合并到目标分支。这通常用于团队协作
6.
合并 是将更改从一个分支集成到另一个分支的过程，它将两个分支的历史记录合并，创建一个统一的历史记录。

每个分支都有自己的历史记录，本地仓库是远程仓库的克隆或副本。
上一个部分在远程仓库进行合并分支的操作，先要获取最新的远程仓库，我们需要在本地也做同样的操作，将从分支合并到主分支的本地副本中。
使用 git pull 命令将本地分支更新到远程分支，此命令将获取所有已进行的更改并将它们合并到我们的本地分支中。
git pull 是本地仓库副本保持与远程仓库的同步的操作。

‍
Pull request，拉取请求，简称PR。
‍
处理 PR的方法 是在 Github 网页端进行处理
‍
申请PR请注意三个点，有助于通过。
1.
写小的PR（Write small pull request） 较小的 PR 更容易、更快速地审查和合并，减少引入错误的可能性，并提供更清晰的变更历史。
2.
先检查你自己的PR（Review your own pull request first） Review+build+test 审查、构建和测试您自己的PR，这样可以帮助你发现，之前可能忽略的错误或拼写错误。
3.
提供背景信息和指导（Provide context amd guidance） 请为您的 PR 编写清晰的标题和描述，以便审阅者能够快速了解你的PR的作用，PR的正文应该包含 PR 的目的、变更概述、以及指向。任何上下文的链接，例如跟踪问题、工单或者之前的对话。
07-如何合并拉取请求 | GitHub 入门
How to merge a pull request | Introduction to GitHub
如何合并拉取请求 | GitHub 入门
​ ​
PR 是指将一组更改从一个分支合并到另一个分支的提议。
‍
两个不同分支上的同一文件的同一部分发生更改时，就会发生合并冲突。
在 Github 上合并 PR 之前，必须先解决所有合并冲突。
例如已经提交过的 PR 分支后又创建个新分支，但是新分支修改的部分是与之前 PR 分支的同一文件的同一行，提供新分支 PR就会产生合并冲突。
如果遇到合并冲突
1.点击按钮 Resolve conflicts 来解决合并冲突
2.或者在终端将更改从主分支拉取到第一次提交PR 分支
new-add-name：git switch man
main：git pull origin main
main：git switch update-name
update-name：git merge main 获取所有这些更改
到文件后接收这些更改后，会受到类似这样的信息
​ ​
其中显示了一些冲突标记，需要接受当前更改，来选择您在此分支上所作的更改，完成上述操作后，暂存并提交更改——git add .
git commit -m "解决合并冲突"
update-name：git status 检查下异常
若无即可推送远程分支
update-name：git push origin update-name

‍
提高个人账户安全性最佳的方法，是配置双因素身份验证（2FA）。
可以选择：身份验证器APP、短信或SMS身份验证、使用 Github APP或硬件身份安全设备。
‍
使用身份证验证器在 Web 上配置双因素身份验证（2FA）
1.下载一个身份验证器应用程序，例如微软身份验证器。
2.打开 Github 设置 -> 访问 -> 密码和身份验证，启用双因素身份验证选项，根据引导完成认证。
‍
通过 Github 个人资料 README 来使我们的 Github 个人资料更具个性
GitHub 的 README 文件比较特殊，它充当 关于我 的页面，这是一种很好的个人介绍，可以让对方更了解你，也更具个人特色。
要创建个人资料 README ，必须先创建一个与您用户名匹配的仓库
1.根据用户名来创建一个仓库
2.设置为公开并使用
3.添加 README 文件后创建仓库
此时 GitHub 会提示你，这是一个特殊仓库。
可以在仓库的 README 文件中添加图片、GIF、社交图标、Github 统计数据等等。

4.怎么判断开源项目质量
Github 上有超过4亿的开源项目，怎么在众多项目分别项目质量高不高？是否值得花时间研究！
着重观察4个指标
1.看右上角的 Star 数，star>1000 项目质量一般都会有保障。
star 是 GitHub 的认可标志，类似于点赞收藏。
用户觉得项目好就会点击star，数字越大说明认可的人越多。
star 超过1万就是热门项目，超过5万就是高热门项目
2.看更新频率
项目都会有更新时间，月内更新算是正常，停更超过半年就要谨慎考虑。
技术日新月异，项目都会层出不穷。
3.看README
README 是项目的使用说明书
好的 README 会写清楚项目能做什么？怎么安装？怎么运行？主要功能？通常会图文并茂。
4.看右侧边栏的License 信息
license 是项目的许可证，许可证决定了你能怎么使用这个项目。
需要知道哪些项目是完全不限制，那些是个人使用可以，商业使用需要开源。
辅助的判断
issues 的数量和活跃度
issues 越多说明用户很多，如果问题大多在几天内就会有人回复说明维护者很活跃。

6.怎么把一个项目运行起来
1.不看源码，最快的方式就是 Release 下载，该页面有打包好的程序，跟安装软件没有区别。
2.无 Release，暂时通过源码下载，下载ZIP
code -> Download ZIP
该方式没有与当前GitHub远程仓库建立关联。无法提交修改，也无法同步更新。
3.在源码上进行修改，通过 git clone，将项目完整的克隆到本地电脑。
